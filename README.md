可能是我太老了，对现在 go/rust 这样没有传统类的语言中使用推荐有组合方式有点心不从心 .. :) 这其实也不是问题，因为我长期以来是写的纯 C 风格代码，有函数就够了。

但最近几年我的 《vdisk》、新《文本处理大师》的开发周期实在太长了，纯 C 风格确实不太适合维护这么庞大的代码，是需要引入更好的管理方式，我使用 delphi 多年，所以最终我的选择是在 go 的基础上实现了传统的面象对象 class ，虽然我知道它有很多缺点，但这是目前对于我的项目最节省时间的方式。

要在 golang 中实现这一目标是真不容易。有些实现方式经历了几种不同的版本，方法并不一致，只是讲述出来供大家参考，并不代表哪种方式更好。

以下按实现的时间顺序，其实也大概等同于需要的程度排名 :)

**1.类成员函数**

这个的实现其实相对简单，在传统纯 C 里就能方便的实现：方法很简单，给结构体增加函数指针就可以了，不过要注意的是传统实现中一般情况下会多一个参数表示结构体指针自己，另外就是会有一个初始化函数给结构体绑定这些函数指针到具体的函数上。

比较幸运的时 golang 已经内置了这一方法，只不过它的语法糖的实现是将第一个指针参数放到函数名前 ... :)

在其他语言里一般在这个参数中会定为 this 或者 self 什么的，会有个固定的“变量名”，但 golang 里则不是，你写的是什么就是什么 ... :) 有时难免选择困难症。

rust 的实现更接近传统 C 不过它对第一个参数有很多语法糖，我们其实最主要是要记住它的 Self 代表这个类（结构体的名称），而 self 代表的是这个类的实例，注意第一个字符大写还是小写 ... :) 有点渗人对吧 ..

【rust】

rust 的成员函数本质上与 golang 差不多，实际上也是静态函数。不过语法糖更多。
实际上语法糖格式更难理解 :)

```fn class_func1(&self, key: &str) -> String```
这样的代码中 self 就是语法糖，实际上它就是
```fn class_func1(self:&Self, key: &str) -> String```

这还不算，实际上这里还有两层语法糖：self 表示的是实际自己，这个和 delphi 等语文差不多，还好理解，关键是 Self 这个首字母大写的，它实际上表示的是当前的类型本身。

我觉得 Self 表示类型本身的设计还是比较好用的，能减少大量的错误和笔误 .. :)


**2.虚函数**

目前为止，golang 和 rust 都没有虚函数，所以函数覆盖基本上做不到，内置的肯定是没有的，因为它们目前都明确不支持继承。

我目前是在部分地方用模板函数来代替了虚函数的功能，更多的地方是用的函数指针实现的。

golang 的函数指针比较强，而且闭包更强，实现起来是比较方便的，而且它似乎能智能判断是否是带有成员函数的函数指针。而且很多时候两者能兼容，我经常感觉很神奇，它内部应该是做了很多工作。

【rust】

理论上 rust 应该也能用模板实现虚函数，不过实际也是用的函数指针。

不过 rust 的函数指针明显更原始，基本上和 c 的差不多，不过好在它对类型定义先后没有要求，所以实现上比 c 简单得多。

另外 rust 的成员是必须初始化的，这在成员是函数指针时多了一层困难：初始化时最好是写上默认函数。不过也有好消息，函数指针也是可以直接指向自己的成员函数的 -- 只要函数签名一样（“函数签名”这个词不知道是什么时候冒出来的，就是函数原型吧）。所以最终也还算好实现，另外还多了一个额外的好处：不需要像 golang 那样先判断函数指针是否是 nil :)
